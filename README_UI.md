# SAIEP UI

JupyterHub now runs as a Kubernetes Deployment. Each notebook is a KubeSpawner Pod
in `saiep-u-<user>`; there is no local notebook process.

For the full operator runbook, menu reference, execution order and
troubleshooting, see **[admin guide.docx](admin%20guide.docx)**.

## Requirements
- Python 3.12 (for the CLI/tests)
- Node.js 20 + npm (image build / `configurable-http-proxy`)
- Docker, kind, kubectl, helm

## Deploy
```bash
python -m saiep_cli
# 3  create the cluster and deploy the SAIEP stack
# 11 redeploy the stack after code changes
```

The stack deployment builds:
- `saiep/jupyterhub:dev` from `hub/Dockerfile`
- `saiep/notebook:dev` from `notebook/Dockerfile`

and loads them into kind. For kubeadm, push the images to a registry and set
`SAIEP_HUB_IMAGE` / `SAIEP_NOTEBOOK_IMAGE`.

## Access
```bash
python -m saiep_cli
# 16 start the local port-forward
```

Then open:

```text
http://127.0.0.1:8000
```

After login, **Home** is `/hub/home`; **Calculs** is `/hub/jobs`. The notebook is
at `/user/<username>/lab` and starts on a Kubernetes Pod. Notebook sessions also
appear in **Mes calculs**, with the same Journal action and MinIO archive as
Argo jobs.

The sizing form controls the Pod's CPU/RAM requests=limits and its maximum
duration. The home directory is a per-user PVC.

## Configuration
```bash
python -m saiep_cli
# 15 write secrets.env (Prometheus token, MinIO credentials)
```

The in-cluster Hub receives its environment from the `saiep-hub-env` Secret,
generated by `saiep_cli`. Do not commit `secrets.env`.
